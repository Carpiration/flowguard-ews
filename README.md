# FlowGuard 2.0 — раннее выявление рисков по аномалиям сетевого трафика

**Тема работы:** разработка модели раннего выявления рисков путём обнаружения аномалий сетевого трафика в кибербезопасности.

**Сайт:** https://carpiration.github.io/flowguard-ews/

FlowGuard — статическое веб-приложение. Модель, разбор файлов и хранилище отчётов работают **в браузере пользователя**: файлы никуда не отправляются, сервер не нужен. Поэтому проект целиком размещается на GitHub Pages.

## Возможности

| Раздел | Что делает |
|---|---|
| **Анализ файла** | PCAP, PCAPNG, CSV (Wireshark, Zeek conn.log, CICIDS2017/2018, UNSW-NB15, произвольные таблицы), JSON/NDJSON (Zeek, Suricata EVE, ECS), текстовый вывод `tcpdump -n`. Формат определяется по сигнатуре; разбор идёт потоково в Web Worker с прогрессом и отменой. |
| **Отчёт** | Оценка риска 0–100, временная шкала «трафик / риск / состояние», вклад каждого детектора, инциденты с доказательствами, MITRE ATT&CK и рекомендациями, детали любого окна, узлы, протоколы, службы, потоки. При наличии разметки — точность, полнота, F1, ROC-AUC и матрица ошибок. |
| **Мониторинг** | Потоковая обработка окон по 2 с: генератор трафика офисной сети, внедрение 7 типов атак, карта взаимодействий, журнал событий. Сеанс продолжается при переходе между разделами и сохраняется в отчёт. |
| **Оценка модели** | Эксперимент на размеченных синтетических данных: сравнение ансамбля с порогом μ+3σ, абляция детекторов, ROC-кривые, интерактивный порог, задержка обнаружения по сценариям, несколько прогонов (среднее ± σ). |
| **Отчёты** | Журнал в IndexedDB: поиск, фильтры, сортировка, массовое удаление, импорт/экспорт JSON. Экспорт отчёта: печать/PDF, автономный HTML, CSV инцидентов и временного ряда (UTF-8 BOM, `;` для Excel). |
| **Методология** | Формулы, признаки, пороги сигнатур, методика оценки и литература; значения берутся из кода модели. |

> Мониторинг работает на генераторе трафика: браузер не может читать сетевой интерфейс. Реальный трафик анализируется из файлов (Wireshark, tcpdump, Zeek, Suricata).

## Модель

1. **Признаки окна** — 13 признаков на временное окно (пакеты, объём, источники, адресаты, порты, попытки соединения, RST, ICMP, DNS, исходящий объём, новые пары, энтропия портов, средний размер пакета); счётчики в лог-шкале.
2. **EWMA-z** — адаптивная норма (медиана/MAD на периоде обучения, затем EWMA), пуассоновская нижняя граница σ, замедленное обучение при подозрении.
3. **CUSUM** — накопление малых устойчивых сдвигов: «раннее предупреждение» для медленных атак.
4. **Isolation Forest** — 100 деревьев, обучение на «вероятно нормальных» окнах, робастная нормировка оценки.
5. **Поведенческие сигнатуры** — сканирование портов, разведка сети, SYN-флуд, DDoS, подбор паролей, утечка данных, C2-маяки, DNS-туннелирование, нетипичные порты (горизонт 60 с, объединение в инциденты).
6. **Слияние** — `R = 100·(1 − (1 − P)·(1 − 0,8·A))` со сглаживанием «быстрый рост, медленный спад»; состояния «норма → предупреждение → тревога».

Результат эксперимента по умолчанию (20 минут, 7 атак, seed 42, 5 прогонов, порог 50):

| Вариант | F1 | ROC-AUC | Задержка | Обнаружено сценариев | Ложных тревог/ч |
|---|---|---|---|---|---|
| Ансамбль FlowGuard | 0,95 | 0,99 | 10 с | 100 % | 0 |
| Статический порог μ+3σ | 0,40 | 0,70 | 80 с | 66 % | 1,8 |

Данные синтетические, поэтому метрики оптимистичнее, чем на реальной сети. Для независимой проверки загрузите размеченный CSV (CICIDS2017, UNSW-NB15) в «Анализ файла».

## Запуск локально

Нужен Python 3.9+ (только стандартная библиотека). Модули ES и Web Worker не работают через `file://`, поэтому нужен локальный сервер:

```bash
python scripts/serve.py
```

Откройте http://127.0.0.1:8000/. Порт можно передать аргументом: `python scripts/serve.py 8080`.

## Проверка

- **В браузере:** откройте http://127.0.0.1:8000/tests/ — тесты ядра и разбора образцов.
- **В Node.js 20+** (так же запускается в CI):

```bash
node tests/run-node.mjs
```

Тесты покрывают разбор адресов, времени и флагов; запись и чтение PCAP; CSV Wireshark/CICIDS; NDJSON Suricata/Zeek; tcpdump; отклонение сжатых файлов; Isolation Forest; CUSUM; метрики и ROC; отсутствие ложных инцидентов на фоне; обнаружение всех сигнатур; сквозной анализ синтетического набора и пяти файлов из `samples/`.

## Образцы данных

`samples/` создаётся независимым генератором на Python (`python scripts/make_samples.py`) — это перекрёстная проверка разборщиков:

| Файл | Формат | Содержимое |
|---|---|---|
| `office-attacks.pcap` | PCAP | сканирование портов, подбор SSH, утечка |
| `covert-channels.pcapng` | PCAPNG, метки в нс | C2-маяк, DNS-туннель |
| `zeek-conn-labeled.csv` | Zeek conn.log (CSV) | сканирование и подбор SSH, с разметкой |
| `suricata-eve.ndjson` | Suricata EVE | утечка данных |
| `tcpdump-scan.txt` | `tcpdump -n` | сканирование портов |

Внешние адреса в образцах и генераторе — из документационных диапазонов RFC 5737.

```

assets/js/workers/         фоновый поток анализа
samples/  scripts/  tests/
```

## Публикация

GitHub Actions (`.github/workflows/pages.yml`) при каждом push в `main` запускает тесты в Node 22 и публикует сайт на GitHub Pages. Сборка не нужна: публикуются исходные файлы.

## Ограничения

- Пороги сигнатур эвристические и требуют калибровки под конкретную сеть.
- Анализируются заголовки и метаданные; содержимое зашифрованного трафика не используется.
- Большие файлы обрабатываются в памяти вкладки (ограничение 2 ГБ на файл).
- Отчёты хранятся в браузере конкретного устройства; для переноса используйте экспорт/импорт JSON.
- Проверено в Chromium (Chrome). Firefox и Safari поддерживают нужные API (модульные Worker, IndexedDB), но отдельно не тестировались.
